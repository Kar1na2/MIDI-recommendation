# MIDI-first transcription and analysis migration

The active route is `WAV or explicitly selected stem → pinned local YourMT3+ → raw MIDI → canonical unquantized note events → symbolic analysis`. It has no import or fallback edge to Basic Pitch, existing `rhythm-harmony-v1`, archived MIDI, automatic correction outputs, pickle/NPZ caches, or listening annotations. `scripts.midi_pipeline.policy` blocks imports of the Basic Pitch package and legacy transcription/analysis packages before loading the model. Run readers accept only completed bundles with the current backend, revision, checkpoint, code and manifest identities and SHA-256 hashes for every artifact.

## Runtime and provenance

The backend uses the author-maintained YourMT3+ Space at revision `5e66c1ea173a8186e0d20432b841d3180cc015b5`, experiment `mc13_256_g4_all_v7_mt3f_sqr_rms_moe_wf4_n8k2_silu_rope_rp_b36_nops`, and checkpoint SHA-256 `ae38e415c79efd5592dcb9b658cdb99ddb11d4c4e1eaa364cab04a052473fc25`. `scripts/midi_pipeline/yourmt3-source-lock.json` locks 78 source and checkpoint files. At runtime every local file is checked against the reviewed SHA-256 manifest; `output/midi_pipeline/verification/source-integrity.json` independently records successful comparison of all 78 files with the pinned remote Git tree (Git blob SHA-1 and checkpoint LFS SHA-256).

The source used here and its Space metadata declare Apache-2.0. The distinct GitHub repository license is GPL-3.0; its license must not be inferred to describe the checkpoint. The pinned Space tree contains no separate checkpoint license, so checkpoint redistribution terms remain unresolved. Keep weights and outputs local until their applicable terms are established.

Tested runtime: WSL CPython 3.11.14; Torch/torchaudio 2.11.0+cu130; Transformers 4.45.1; Lightning/PyTorch-Lightning 2.6.6; NumPy 1.26.4; SciPy 1.17.1; SoundFile 0.14.0; pretty-midi 0.2.11.post0; Matplotlib 3.11.2; see `scripts/midi_pipeline/requirements-wsl-tested.txt`. Hardware: NVIDIA RTX 4060 Ti, 16 GiB VRAM. The regression run measured approximately 400 MB peak CUDA allocation for the 12-second case. Inference uses deterministic settings where supported, float32, and batch-size 1. Audio segments stay on CPU and the model transfers only a batch to the GPU. The inference-only Python environment is not cleanly isolated from the main venv (`include-system-site-packages=true`), so the import policy and regression tests enforce separation at runtime; a separately built minimal environment remains desirable.

YourMT3+ emits estimated instrument programs, pitches and note times; it does not emit calibrated note confidence. The upstream note writer sets velocity to 100 and emits a synthetic 10 ms drum duration. Those limitations are recorded in every note document. The model's MIDI timing remains crop-relative and unquantized in `raw.mid`; `notes.json` adds the declared source offset without modifying the raw MIDI. Analytical beat coordinates are optional, require an explicit reviewed BPM, and never rewrite note timing.

Run identity contains the source file SHA-256, source/stem identity, separation identifier, source clock/window, checkpoint and revision, preprocessing/configuration, implementation digest, dependency versions, and analysis version. Run directories are immutable/write-once. A failed backend writes `transcription_unavailable`; consumers reject it. A historical MIDI can enter only by manually violating the explicit run/provenance contract, and is never discovered by a folder scan or fallback.

## Symbolic analysis

`analysis.py` groups simultaneous attacks around a fixed 30 ms first-onset tolerance, then reports raw IOIs and durations, ratios of median IOI, optional beat-relative offsets/subdivisions, intervals, contours, overlap pairs, repeated rhythm/contour/full-note candidates, chord-template intersections, arpeggio candidates, and coarse phrase/overlay observations. Recurrence compares variable attack-sequence lengths from 3–24, every offset within a bounded local search region, and adjacent lengths using a descriptor shortlist followed by DTW. It allows arbitrary seconds between events, tempo scaling and transposition-tolerant interval contours. Long tracks are searched in overlapping 240-attack contexts, so recurrence candidates farther apart than that context can be missed. This is approximate candidate generation: centroid/width descriptors can collide, polyphonic voice leading is not modeled, and not every musical recurrence can be found. Percussion keys remain drum classes and are excluded from melody, arpeggio and chord claims.

Chord candidates require simultaneous predicted notes and explicit note IDs. An arpeggio candidate requires a monophonic sequence whose pitch classes form a template triad and whose successive pitches move in one direction. Phrase beginnings, endings, gaps and late first attacks are observations rather than semantic section labels. There is no inferred meter/downbeat, pedal release, or verified instrument program. A low DTW cost is not confidence.

`review.html` aligns the source crop and note timings on the source-recording clock. `prediction-sine-preview.wav` is a neutral pitched-note rendering, not a reconstruction of the original arrangement. The page has a player, seekable piano roll, MIDI and JSON links, and uncertainty notes. Static piano roll, onset and source-aligned plots support inspection. Listening annotations are kept out of these prediction outputs.

## Meaningful Love evidence

The original diagnostic used Silo “Meaningful Love” Other WAV SHA-256 `e4b05c7ce723a844ffb53f6289ada92d3841370f1c97aa4e96deac05612dc93b`. A 6–18 second run produced 47 notes over three predicted tracks, with one missing-onset and five segment-tie decoder warnings. The median MIDI note duration was about 30 ms. The piano track contains conspicuous gaps while the source waveform continues, including approximately 10.3–14.3 seconds. The 6–12 versus 12–18 comparison is a normalized predicted-sequence DTW, not the old acoustic spectral score: track 0 costs were 0.123 rhythm, 0.152 contour and 0.201 full-note. The other two predicted tracks did not have enough attacks in both windows for a comparison. These values do not validate a repeated motif.

The synthetic suite uses independent labels, not the model's own output. In one frozen run, onset-and-pitch F1 was 0 for silence-adjacent sustained (2 reference notes, 0 predicted), overlap (4, 0), and arpeggio (12, 0); 0.50 for instrumentation changes (4/12 notes recalled; 0 false positives); and 0.80 for two tempo regions (8/12 recalled; zero false positives, conditional pitch accuracy 1.0, mean onset error 0.00075 s, matched-note offset error 0.028 s). Chosen target motif recurrence F1 was 0 in all annotated repeated cases. Empty silence has no positive-note F1 and is reported as undefined, not a perfect score. The fixture evaluator also reports false/missing notes and program correctness; a few clean synthetic tones are an engineering check, not a real-music benchmark.

There are no independently reviewed pitched-note labels for Meaningful Love, so no note precision, recall, chord, arpeggio, motif or pitch accuracy is claimable on that recording. The audible-vs-MIDI gaps, 30 ms note duration and decoder warnings are transcription-side failures. The MIDI event grouping and DTW analysis operate on those events and cannot recover notes the transcriber missed. This separates the new transcription failure from the former waveform algorithm's independent limitations.

## Existing separation and next validation

Keep the existing `htdemucs_ft` separator; Basic Pitch and Demucs are different stages. Existing stem-producing projects and the dedicated four-stem source remain read-only. The regression checks the original mix and four dedicated/library stems; it does not assume Other is complete. Fresh separation through `separation.py` requires already-cached reviewed Demucs weights and writes to a new fingerprinted directory. The required `htdemucs_ft` weights were not present in the WSL Torch cache during this implementation, so no alternative split was run or downloaded. The existing Demucs library configuration uses four single-stem component models. Verify a source stem's manifest or label its separation version unknown; do not silently treat a folder name as model provenance.

Continue in this order:

1. Collect reviewed complete note labels for Meaningful Love and representative arranged audio; keep composition-level train/validation/test separation.
2. Inspect the 47-note MIDI against the original mix and each stem; resolve the instrument-role and missing passage questions manually against aligned audio, not the automatic chord guesses.
3. Review timing and decoding behavior on independently labeled polyphonic/real arrangements. The current synthetic suite shows the checkpoint does not yet generalize to these synthetic examples, so deployment as an accurate full-library transcriber is not supported.
4. Acquire Demucs weights intentionally, hash them, and compare fresh separated stems against the original mix if the current stem results justify it.
5. Revisit thresholds or model choices only from a declared validation set; do not tune the Meaningful Love display until it produces positive motifs.
6. Run `python -B -m unittest scripts.midi_pipeline.test_pipeline -v`, validate complete labels with `evaluation.py`, and review outputs through `review.html`. Do not send this path over the music library until held-out evaluation and listening review justify it.

Historical processing remains available only by explicit `make legacy-<target>` invocation through `archive/Makefile.legacy`; old Basic Pitch and corrected MIDI are quarantined from these run readers. No historical file or source audio is deleted. The separate old 1nonly “Meaningless Love” analysis remains Basic Pitch-dependent in that historical graph; it is a different song and diagnostic. The Silo “Meaningful Love” `rhythm-harmony-v1` diagnostic did not use Basic Pitch at all.
